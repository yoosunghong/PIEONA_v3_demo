# ILLOA 생활 콘텐츠 — Phase 1 구현

## 기존 코드 분석

- 클라이언트: React 19, Three.js. `src/main.jsx`가 마을 세션·대화·모달을 관리하고 `src/Scene.jsx`가 렌더링과 로컬 이동을 처리한다.
- 서버: Express, Socket.IO, Node SQLite. `server/app.mjs`의 인증 세션과 마을별 연결 목록을 재사용한다.
- 기존 벤치 기능의 `createSitMotion`은 네 캐릭터의 실제 뼈대를 사용하므로 낚시 앉기에도 재사용한다.
- 기존 `users.village`는 꾸미기 배치이고 `gold`는 미니게임 재화다. 생활 아이템은 별도 테이블로 추가하고 두 데이터를 재해석하지 않는다.
- 기존 이동 좌표는 클라이언트가 전송하고 서버가 유효 범위를 검사하는 프로토타입 구조다. 이번 구현도 그 위치 체계에 의존하며, 이동 속도까지 판정하는 전용 게임 서버를 추가하지 않는다.

## 구현 범위

- 마을 앞 바다와 나무 낚시 데크, 복수 캐릭터를 고려한 네 개의 고정 앵커.
- 가까이에서 E 또는 화면 버튼으로 진입, 서버 승인 후 자리 정렬과 앉기.
- 무료 낚싯대, 캐스팅·낚싯줄·찌·물결 연출.
- 45초 주기, 성공률 70%, 성공 후 일반/고급/희귀/특별 72/22/5/1% 조건부 추첨. 같은 희귀도 안에서는 균등 추첨.
- 세션 획득량·물고기 목록·다음 판정 시간·종료 버튼. 이동과 점프로도 활동 종료 가능.
- 마을 보관함 오브젝트 및 상단 바로가기. 카테고리, 수량 합산, 상세 설명, 첫 발견 일시와 획득자.
- 7종 물고기 도감, 미발견 실루엣, 전체·희귀도별 발견 현황.
- 계정 단위 저장이므로 자아 슬롯을 전환해도 보관함은 공유된다. 슬롯과 수량의 게임상 제한 및 유통기한은 없다.

## 구조와 데이터 신뢰성

`shared/life.mjs`는 아이템 정의, 밸런스, 앵커와 상호작용 판정을 공유한다. `server/life.mjs`가 활동의 시작·정산·종료를 처리하고, `src/Life.jsx`는 화면 상태와 보관함을, `src/lifeWorld.js`는 3D 연출을 담당한다.

API:

- `GET /api/me/life`: 인증한 본인의 활동·보관 수량·발견 기록·아이템 정의.
- `life:start {anchorId}`: 마을 연결, 소유권, 거리, 다른 활동과 자리 사용 여부를 확인한 후 시작. 중복 요청은 진행 중인 세션 반환.
- `life:stop`: 진행 중인 활동 종료. 반복 종료는 추가 보상을 만들지 않는다.
- `life:state`: 본인에게만 결과·세션 상태 알림. 자세는 기존 마을별 메시지로 전달.

테이블:

- `life_sessions`: 소유자·행위자·앵커·시작/정산/종료 시각·시도/획득 횟수. 진행 중 행위자와 마을별 앵커의 고유 제약.
- `inventory_entries`: 계정·아이템별 수량.
- `acquisition_events`: 획득자·출처·시각과 세션별 판정 회차. `(session_id, cycle)` 고유 제약.
- `fish_discoveries`: 계정·물고기별 최초 발견 기록.

획득 이벤트, 보관 수량, 첫 발견과 정산 체크포인트는 하나의 SQLite 트랜잭션으로 확정한다. 클라이언트는 수량·추첨 결과·보상 시각을 지정할 수 없다. 테이블 생성은 기존 DB에 추가되며 기존 사용자 데이터는 삭제하지 않는다.

## 접속 및 호환성

Phase 1은 온라인 활동이다. 마지막 마을 연결이 종료되면 완성된 주기까지만 정산하고 중지한다. 같은 마을에 다른 탭이 남아 있으면 유지한다. 다른 마을에 있는 탭의 이탈은 원래 마을의 낚시에 영향을 주지 않는다. 서버를 재시작하면 남은 활성 세션을 종료하며 서버 중단 시간의 보상은 지급하지 않는다.

기본 가장자리 조경 중 데크와 겹치는 부분은 장면에서 가려 통로를 확보한다. 저장된 배치 데이터와 기존 꾸미기 저장·복원 규칙은 유지한다. 네 앵커는 준비되지만 현재 낚시 진입은 마을 주인 한 명에게만 허용한다.

## 검증과 다음 단계

최종 검증: `npm test` **211/211 통과**, `npm run build` 성공. 브라우저 콘솔 오류 없음. 상세 결과는 `test-results/life-phase1/final-tests.txt`와 `build.txt`에서 확인할 수 있다.

`tests/life.test.mjs`에서 추첨 경계, 인증·거리·권한, 여러 탭의 중복 시작, 45초 경계, 반복 정산, 실패 트랜잭션 롤백, 이동·마을 이탈, 다른 마을 탭 이탈, SQLite 재시작 보존 및 오프라인 보상 제외를 검증한다.

브라우저에서 키보드 및 화면 버튼 진입 → 실제 정어리 2마리 획득 → 종료 → 보관함 수량 2 → 도감 1/7 및 최초 발견 기록을 확인했다. 모바일 390px 도감과 데스크톱 상세 패널도 확인했다. 시각 검증용 서버는 별도 포트와 메모리 DB를 사용했으며 물고기 추첨은 테스트에서만 고정했다.

전체 회귀 검사에서 기존 테스트 두 건의 조건도 수정했다. 조각상 11개 테스트는 0.5 간격으로 배치해 기존 0.8 간격 검증에 걸렸으므로 유효한 좌표와 정확한 HTTP 200·저장 개수 검증으로 바꿨다. 게 게임 기권 테스트는 주기적인 일반 상태 메시지와 최종 메시지의 도착 순서에 의존했으므로 `ended` 상태를 기다리게 했다. 제품의 소품 제한이나 게 게임 규칙은 변경하지 않았다. 검증 로그와 화면 캡처는 로컬 `test-results/life-phase1/`에 있다.

Phase 2의 자연어 명령·AI 동반 낚시, Phase 3의 텃밭·요리, Phase 4의 자율 활동·오프라인 정산·관계 기억은 이번 범위에 포함하지 않는다. 요리 버튼은 준비 중으로 표시하며 소비 API는 아직 노출하지 않는다. 이후 AI 액션 라우터는 이 서버 활동 로직을 호출하고, 행위자 모델을 플레이어/동반자로 확장해야 한다.
