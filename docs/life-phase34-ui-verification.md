# Phase 3·4 실제 UI 검증 — 2026-10-23

## 환경과 결과

Node 22.17.1, 운영 빌드, 기존 `data/pieona.sqlite`, 로컬 서버 `http://127.0.0.1:3000`에서 검증했다. 브라우저는 데스크톱 1440×1000과 모바일 390×844 뷰포트를 사용했다. 실제 휴대전화의 Safari/Chrome 검증과는 구분한다.

초기 샌드박스 실행에서는 브라우저 연결이 시간 초과되고 셸 HTTP 연결도 소켓 권한 오류가 났다. 허용된 실행 환경에서 서버를 재시작한 뒤 동일한 주소로 정상 연결했다. 다른 URL·포트나 터널로 우회하지 않았다.

기존 계정 대신 별도 생활 검증 계정을 만들었다. 기존 11개 계정은 삭제·수정하지 않았으며, 최종 계정 수는 12개다. 검증 계정의 자율·오프라인 활동은 마지막 중단 요청으로 껐다.

## 수정

- 새 소품·팻말·방명록·기본 장식의 배치/이동/복원 시 텃밭·조리대·보관함·데크와 텃밭/조리대 작업 접근 지점을 보호한다. 편집기와 서버가 같은 규칙을 사용한다.
- 기본 팻말이 텃밭과 겹쳐 생성되던 좌표를 이동했다. 명시적으로 저장된 기존 배치는 유지한다. 기존 기본 나무는 이미 생활 영역에서 렌더링을 숨기고 있었으며 나무 좌표 자체를 변경하지 않았다.
- 모바일 AI 생활 체크박스를 설명과 한 줄로 정렬했다. 전역 `label`의 세로 방향 스타일이 원인이었다.
- 마을 걷기 중에는 아바타 정보 카드를 숨겨 텃밭과 이동 시야를 확보했다.
- 짧은 이동 키가 프레임 사이에서 끝나 생활 작업이 계속되던 문제를 수정했다. `keydown`에서 진행 중 작업/낚시를 즉시 중단한다.
- 기존 테스트의 정상 배치 좌표 중 새 생활 시설 영역에 들어간 좌표를 유효한 빈 곳으로 바꿨다. 기존 배치 보존 검증과 새 충돌 거절 검증을 함께 유지했다.

## 실제 Gemini

실제 `.env` 연결로 합성 문장 9건을 확인했다. 애매한 허브 생선구이 요청, 부정, 인용, 함께/혼자 낚시, 복수 수량·시간 제한 거절, 정확한 자동 요리 허용과 해제가 모두 기대한 액션을 반환했다. 관찰한 요청 시간은 3.26–7.96초이며 일반적인 응답 시간 보장은 아니다.

UI에서도 자연스러운 요리 요청이 실제 모델을 거쳐 정어리 1마리와 허브 1개를 소비하고 허브 생선구이 1개로 완료됐다. 다음 모델 요청에 응답이 오기 전에 모두 중단을 누르면 늦은 요청을 실행하지 않는 서버 답변이 표시됐다. 키와 대화/기억 원문은 검증 결과 로그에 기록하지 않았다. 직접 호출의 최초 판정식에서 잘못 참조한 참가자 필드는 실제 스키마의 `actor`와 `JOIN_FISHING`에 맞춰 기록된 액션을 재평가했다.

## 남은 검증

- 실제 휴대전화의 터치·소프트 키보드·회전·성능과 외부 Cloudflare 접속은 이번 검증에 포함하지 않았다.
- 기존 사용자 저장 배치는 자동으로 재배치하지 않는다. 생활 시설과 이미 겹치는 오래된 소품은 편집기로 옮겨야 하며 신규 배치·이동·복원에는 보호 규칙이 적용된다.
- 기존 사용자의 여러 실기기 접속·자아 전환은 별도 실제 사용자 검증이 필요하다. 격리 HTTP/Socket.IO 회귀의 여러 탭·자아 전환·중복 정산 검증은 통과했다.
- Gemini의 확률적 해석 품질은 이번 합성 표본의 범위다. 장기 네트워크 지연, 호출 제한과 모델 변경은 계속 점검한다.
- 다수 사용자 100ms 틱과 재접속 정산 성능 측정, 보존 기간·로그 회전 설계가 다음 개발 우선순위다.
