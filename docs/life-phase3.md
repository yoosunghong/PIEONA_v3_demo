# Phase 3 — 텃밭과 기본 요리

## 기존 시스템과 연결

Phase 2의 `installLife`, `lifeActionSchema`, 대화 API, Socket.IO 마을 멤버와 계정 공통 `inventory_entries`를 확장했다. 플레이어 버튼과 자연어 명령 모두 같은 `createGardening` 서비스에서 검증·예약·완료 처리한다. 기존 낚시 확률과 7종 물고기 도감은 유지한다.

## 사용 방법

- 마을 상단 **텃밭**, **요리** 버튼 또는 월드의 텃밭·조리대 근처에서 **E**로 연다. 보관함 안에서도 탭을 전환할 수 있다.
- 텃밭은 3칸이다. 무료 씨앗을 선택하면 플레이어가 밭으로 이동하고 2초 작업 후 심는다. 허브 5분, 토마토 10분, 꽃 20분 뒤 각 1개를 수확한다.
- 성장 시간은 서버 타임스탬프로 계산한다. 접속 종료와 서버 재시작 중에도 성장하며, 성숙한 작물은 시들지 않는다. 수확 후 빈 밭이 되며 자동으로 다시 심지 않는다.
- 요리는 조리대로 이동해 2초 작업 후 재료를 소비하고 음식 1개를 보관함에 저장한다. 시작 시와 완료 시 모두 재료를 검증한다.
- 플레이어와 AI는 각자 한 작업씩 수행할 수 있다. 동일 밭은 작업 중 예약된다. 같은 재료를 두 작업이 계획했더라도 완료 시 수량 검증으로 중복 소비를 막는다.
- 이동 입력, 중단 버튼 또는 “그만하자”로 완료 전 작업을 취소한다. 마지막 내 마을 접속 종료·자아 전환도 작업을 취소한다. 이미 심은 작물과 완료한 획득물은 남는다.

| 요리 | 재료 |
| --- | --- |
| 생선구이 | 물고기 1마리 |
| 허브 생선구이 | 물고기 1마리 + 허브 1개 |
| 해산물 모둠 | 서로 다른 물고기 3종, 각 1마리 |
| 토마토 샐러드 | 토마토 1개 |

명시적 선택이 없으면 일반·고급 물고기만 선택한다. 희귀·특별 물고기는 요리 화면에서 직접 고르거나 이름을 명시해야 한다. 물고기를 사용해도 최초 발견과 과거 획득 기록은 사라지지 않는다. 토마토 샐러드는 기획서의 기본 3개 레시피에 추가해 토마토의 사용처를 제공한다.

## 자연어 명령

| 예시 | 동작 |
| --- | --- |
| 허브 좀 심어줘 | 빈 밭 1칸에 AI가 이동해 심기 |
| 2번 텃밭에 토마토 심어줘 | 지정 밭에 심기 |
| 텃밭 수확해줘 | 현재 성숙한 작물만 수확 |
| 꽃 다 자랐어? | 서버의 실제 성장 상태 조회 |
| 허브 생선구이 만들어줘 | 재료 확인 후 AI가 조리대로 이동해 요리 |
| 황금도미 구워줘 | 명시한 물고기로 생선구이 만들기 |
| 오늘 뭐 수확했어? / 방금 뭐 요리했어? | AI의 실제 완료 기록 조회 |
| 허브 몇 개 있어? | 현재 보관 수량 조회 |
| 너만 중단해 / 나만 중단해 / 그만하자 | 대상별 생활 작업 중단 |

Gemini 구조화 응답에 새 액션을 추가했고 대표 한국어 명령은 API 키 없이도 처리한다. 작업 시작 답변은 이동·예정만 설명한다. 완료 알림과 최근 작업 결과에는 서버가 저장한 실제 수량을 표시한다. 방문자는 마을 주인의 작업·보관함을 제어하거나 조회할 수 없다.

## 저장 구조와 일관성

- `garden_plots`: 계정·밭별 작물, 심은 시각, 성숙 시각, 심기 버전 UUID, 당시 행위자 이름.
- `life_operations`: 요청 UUID, 행위자 종류·이름·자아 슬롯, 검증된 계획, 상태, 완료 결과. 계정별 요청 UUID와 행위자별 진행 작업에 고유 제약을 둔다.
- `garden_reservations`: 계정·밭별 작업 예약.
- `inventory_changes`: 작업별 소비 음수/획득 양수 기록. 낚시의 기존 획득 기록과 분리해 수확·요리 출처별 조회를 제공한다.

작물 비우기, 재료 차감, 음식·수확물 지급, 변화 기록, 작업 완료를 한 SQLite 트랜잭션으로 처리한다. 하나라도 실패하면 전부 되돌린다. 수확은 예약 당시 심기 UUID도 검증해 이전 화면의 요청이 새 작물을 수확하지 못한다. API의 `requestId` 재전송은 기존 작업/결과를 반환한다. 프런트엔드는 네트워크 오류 후 같은 작업 재시도 시 이 키를 재사용한다.

서버 재시작 시 미완료 작업과 예약만 취소한다. 완료된 작물·재료·음식·영수증은 유지한다. 이전 스키마에 추가 테이블만 생성하며 운영 적용에는 서버 재시작과 브라우저 새로고침이 필요하다.

## 검증과 범위

최종 `npm test`: **231개 통과, 실패 0개**. `npm run build`: **통과**. 일반 대화의 “반복해줘”가 생활 자동화 명령으로 잘못 분류되던 회귀도 수정하고 전체 테스트를 재실행했다.

실제 HTTP·Socket.IO 통합 테스트로 이동 후 작업, 3칸 제한, 성장 시간 경계, 중복 요청, 밭 예약, 자연어 전체 흐름, 레시피별 재료, 희귀 물고기 보호, 동시 소비, 중단·이탈·늦은 AI 응답, 방문자 권한, 전체 수확 롤백, SQLite 재접속을 검증한다. Gemini는 기존 구조화 출력 테스트에서 모의 응답을 사용하며 유료 외부 호출은 하지 않았다.

프런트엔드 프로덕션 빌드는 통과했다. 브라우저 미리보기는 이 세션에서 WebView 연결이 반복 시간 초과되어 데스크톱·모바일 시각 검증은 완료하지 못했다.

Phase 4의 자동 반복·오프라인 수확/요리, 선물, 음식 먹기, 꽃 장식 배치는 포함하지 않는다. 꽃과 음식은 현재 보관함에서 수량과 설명을 확인한다.
