# Phase 2 — AI 동반자 행동 연동

## 코드 분석 및 연결 지점

기존 대화는 `server/app.mjs`의 메시지 API → `assembleContext` → `generateAnswer` → 대화/기억 저장 순서였다. Phase 1은 `server/life.mjs`가 플레이어의 위치·낚시·획득 정산을 관리하고 `life:state`, `village:members`와 `village:move`로 화면을 갱신했다.

Phase 2는 이 흐름을 재사용한다. 별도의 보상 시뮬레이션이나 가짜 AI 계정을 만들지 않는다.

## 구현

- `server/lifeActions.mjs`: 허용 액션 스키마, 대표 한국어 명령의 로컬 해석, Gemini 구조화 응답 스키마, 실제 획득 수량 표현, 한국 날짜 경계.
- `server/ai.mjs`: 일반 메시지 생성에 선택적 `action` 출력 추가. 액션 생성은 현재 메시지 API에만 활성화되며 토픽 대화에는 영향을 주지 않는다. 정상적인 잡담은 기존 페르소나/기억 흐름을 유지한다.
- `server/app.mjs`: 요청/응답 사이의 세션·자아·공개 설정 재검증 이후 액션 실행. 결과 응답은 서버가 작성한다. 액션 발화를 일반 공개 기억으로 자동 저장하지 않는다. 중단 명령은 기존 LLM 요청 잠금을 우회하고 해당 잠금을 제거하지 않는다.
- `server/life.mjs`: `PLAYER`, `COMPANION` 두 행위자, `Idle → Moving → Fishing → Idle`, 자리 예약, 이동 경로, 공통 정산, 조회 및 결과 보고.
- `src/Scene.jsx`: 동반자를 별도 캐릭터로 표시하고 서버 이동을 보간한다. 함께 낚시할 때 플레이어도 예약한 자리로 걸어간다. 낚시 모션·낚싯대·카메라는 Phase 1을 재사용한다.
- `src/main.jsx`, `src/Life.jsx`, `src/life.css`: 마을 내 대화창 유지, 두 행위자의 진행 상황·개별 중단·모두 중단, 보관함 열기, 동반자 획득 알림, 보관함의 최근 결과 요약.
- `src/GameHub.jsx`: AI 동반자는 실제 접속 이웃이나 게임 초대 대상에 포함하지 않는다.

## 사용 예시

| 입력 | 실행 |
|---|---|
| 너 먼저 낚시하고 있어 | AI가 빈 자리를 예약하고 이동 후 낚시 |
| 우리 낚시하러 갈까? / 같이 낚시하자 | 인접한 두 자리를 확보하고 이동. 기존 플레이어 낚시는 유지 |
| 물고기 좀 잡아와 | AI가 3회 판정 후 자동 중단·결과 알림 |
| 이제 그만하자 | 두 캐릭터의 낚시 또는 이동 중단 |
| 너만 중단해 / 나만 중단해 | 지정한 캐릭터만 중단 |
| 오늘 고등어 몇 마리 잡았어? | 한국 시간 오늘의 AI 고등어 획득 기록 |
| 오늘 내가 뭐 잡았어? / 오늘 우리 뭐 잡았어? | 플레이어 / 두 캐릭터의 실제 획득 기록 |
| 최근 낚시 결과 알려줘 | 최근 AI 낚시 세션의 획득 기록 |
| 보관함에 물고기 몇 마리 있어? | 현재 공통 보유량 |
| 보관함 열어줘 | 보관함 UI 열기 |

일반 낚시는 사용자가 중단할 때까지 이어진다. 결과 보고 요청의 3회는 성공 3회가 아니라 **판정 3회**다. 결과가 없으면 0마리라고 답한다. “도미 잡으면 알려줘” 같은 조건부 알림 예약, 따라오기·요리·선물 등 미지원 명령은 실행하지 않고 안내한다.

## 데이터 및 일관성

기존 `life_sessions`에 `actor_kind`(기본 PLAYER), `actor_name`, `avatar_slot`, `task_limit`을 추가한다. 획득 기록은 세션을 통해 행위자 종류와 당시 이름을 구분한다. 인벤토리와 도감 테이블의 기존 데이터는 유지한다.

- 활성 세션 고유 키: `(actor_id, actor_kind)`, 예약 자리 고유 키: `(owner_id, anchor_id)`. 이동 중인 세션도 두 제약에 포함한다.
- 함께 시작할 때 필요한 세션을 한 트랜잭션으로 예약한다. 동일 요청 반복은 기존 세션을 재사용한다.
- 이동 도착 시점부터 45초를 계산한다. 서버가 움직임과 보상을 확정하고 클라이언트 좌표는 보상을 발생시키지 않는다.
- 물고기 지급·획득 이벤트·도감·정산 체크포인트는 기존 공통 트랜잭션으로 처리한다. AI도 동일한 70% 성공률/희귀도 확률을 사용한다.
- 중단 또는 마지막 내 마을 연결 종료 시 명령 세대를 갱신한다. 그 이전에 시작한 LLM 응답이 뒤늦게 도착해도 새로운 활동을 시작할 수 없다.
- 여러 탭 중 하나가 떠나도 남은 내 마을 탭이 있으면 유지한다. 다른 마을 탭 종료는 내 마을 활동에 영향을 주지 않는다.
- 자아 전환 시 기존 활동을 중단한다. 계정 공통 인벤토리와 과거 획득 기록은 유지한다.
- 서버 재시작 시 이동·낚시는 종료 처리한다. 오프라인 보상은 Phase 2 범위에 포함하지 않는다.

## 검증

`npm test`: 기존 테스트를 포함한 전체 219개 통과. 이후 추가한 한국 자정 경계·Phase 1 마이그레이션 2개를 포함해 생활 콘텐츠 테스트 16개 재검증 통과. `npm run build`: 통과.

신규 통합 검증은 실제 HTTP 대화 API와 Socket.IO 접속을 사용한다. 자연어 해석, 실제 이동, 자리 예약, 중복 명령, 두 행위자의 보상 구분, 오늘/최근/보관함 질문, 3회 결과 보고, 방문자 거부, 잘못된 모델 출력, 미니게임 충돌, 중단과 지연 응답 경합, 마지막 탭 이탈, Gemini 스키마를 확인했다. Gemini 연결은 모의 응답으로 검증하며 실제 유료 외부 호출은 사용하지 않았다.

브라우저 검증은 운영 DB와 분리된 메모리 DB에서 수행했다. 자연어로 함께 이동·나란히 앉기·낚싯대 연출·각각의 실제 획득·기록 질의·중단·보관함을 확인했다. 모바일 390×844에서도 대화와 중단 조작을 확인했다. 운영 서버에 적용하려면 서버를 재시작하고 브라우저를 새로고침한다.
