# PIEONA — 3D 아바타 소셜 플레이테스트

## 생활 콘텐츠 Phase 1–4 — 낚시·텃밭·요리·AI 자율 생활

**AI 생활**에서 자율 활동, 오프라인 활동, 재파종, 허용 요리를 설정할 수 있습니다. 기본은 꺼져 있으며 **“자율 활동 시작해줘”**, **“내가 없는 동안 텃밭 관리해줘”**로도 켤 수 있습니다. 실제 작업은 규칙 기반으로 선택하고 명시적 요청을 우선합니다. **“그만하자”**는 자율·오프라인 모드도 끕니다. 자동 요리는 지정한 레시피만 사용하고 희귀 물고기는 소비하지 않습니다.

오프라인은 최대 **2시간**, 낚시 판정 **80회**, 작물 수확 **18개**, 음식 **6개**까지 한 번만 정산합니다. 재접속 보고와 **“없는 동안 뭐 했어?”**는 실제 획득·소비 기록을 보여 줍니다. **우리의 추억** 탭과 **“우리 함께한 추억 알려줘”**에서는 공동 낚시·희귀 발견·첫 수확·요리 사실을 확인합니다. 관계 기억은 현재 자아와 소유자에게만 제공하며 잊을 수 있습니다. [Phase 4 구현 기록](docs/life-phase4.md) · 테스트: `node --test --test-concurrency=1 tests/autonomy.test.mjs`.

**내 마을 걷기**에서 마을 앞 바다의 나무 데크 가까이 이동하면 **E 낚시하기** 버튼이 표시됩니다. E 키 또는 버튼을 누르면 앉아서 자동 낚시를 시작합니다. 기본 낚싯대는 무료이며 서버가 45초마다 70% 성공률로 판정하고, 성공 시 물고기 한 마리를 보관함에 저장합니다. 낚시 종료 버튼 또는 이동 입력으로 중단할 수 있습니다.

**보관함 · 도감** 버튼이나 마을의 보관함 오브젝트로 보유 수량·첫 발견 기록·7종 도감을 확인합니다. 보관함은 계정 단위로 자아 슬롯 간 공유하며, 수량 제한과 유통기한은 없습니다. 내 AI 동반자도 같은 낚시 시스템으로 물고기를 획득하고, 최초 획득자에 AI 여부를 표시합니다. 마지막 내 마을 연결이 끊기거나 자아를 바꾸면 둘의 활동은 종료되고, 기존 획득 아이템은 SQLite에 남습니다.

**텃밭** 버튼에서 3개 밭에 무료 씨앗을 심습니다. 허브 5분·토마토 10분·꽃 20분 후 수확할 수 있고, 접속하지 않아도 성장하며 시들지 않습니다. **요리** 버튼에서는 생선구이, 허브 생선구이, 해산물 모둠, 토마토 샐러드를 만듭니다. 플레이어나 AI가 작업 장소로 이동한 뒤 작업을 완료하면 수확물을 보관함에 넣거나 요리 재료를 음식으로 바꿉니다. 희귀 물고기는 직접 지정해야 요리에 사용합니다.

**“허브 좀 심어줘”**, **“텃밭 수확해줘”**, **“꽃 다 자랐어?”**, **“허브 생선구이 만들어줘”**, **“오늘 뭐 수확했어?”**, **“방금 뭐 요리했어?”**로 AI에게 부탁할 수 있습니다. “그만하자”로 완료 전 작업을 취소하면 재료를 사용하지 않습니다. 음식 먹기·선물·장식 배치는 후속 단계입니다. [Phase 3 구현 기록](docs/life-phase3.md) · 테스트: `node --test --test-concurrency=1 tests/garden.test.mjs tests/life.test.mjs tests/life-actions.test.mjs`.

내 아바타 대화창에 **“너 먼저 낚시하고 있어”**, **“같이 낚시하자”**, **“이제 그만하자”**, **“오늘 고등어 몇 마리 잡았어?”**, **“보관함 열어줘”**라고 말해 보세요. 대화창은 마을에서도 유지됩니다. 두 캐릭터는 서버가 예약한 자리로 실제 이동하며, 이동 중에는 보상을 받지 않습니다. **“물고기 좀 잡아와”**는 3회 판정 후 중단하고 실제 결과를 알립니다. **“너만 중단해”** / **“나만 중단해”** 및 상태 카드 버튼으로 각각 멈출 수 있습니다. 오늘 조회는 한국 시간 기준이며, 보유량과 획득 기록을 구분합니다.

Gemini는 허용된 JSON 액션을 출력하고 서버가 권한·상태·중단 여부를 검증합니다. 대표 명령은 네트워크 지연 없이 로컬에서도 동작합니다. 실행 결과와 수량은 서버 기록으로 답하며, 방문자는 다른 사람의 동반자나 보관함을 제어·조회할 수 없습니다. [Phase 2 구현 기록](docs/life-phase2.md) · 테스트: `node --test --test-concurrency=1 tests/life.test.mjs tests/life-actions.test.mjs`.

서버 코드도 변경되므로 `start-server.bat`으로 재시작한 뒤 브라우저를 새로고침하세요. 기존 DB에는 생활 콘텐츠 테이블이 자동으로 추가됩니다. 구조와 구현 범위는 [Phase 1 구현 기록](docs/life-phase1.md)에 정리했습니다. 관련 테스트: `node --test --test-concurrency=1 tests/life.test.mjs tests/world.test.mjs tests/benches.test.mjs`.

[게임 열기](https://pieona.yoosung.dev) · 로컬 주소: http://127.0.0.1:3000

`pieona_Avatar.md`의 핵심 재미를 검증하는 개인 PC 호스팅 웹 프로토타입입니다. React + Three.js, Node.js/Express + Socket.IO, SQLite로 구성했습니다. 모바일 온디바이스 추론과 UE5 렌더러 대신 웹 3D 및 서버 Gemini 추론을 사용합니다.

## 시작과 종료

Windows에서는 `start-server.bat`을 더블클릭하면 기존 서버·터널을 종료하고 최신 코드를 빌드한 뒤 **CMD 창 안에서 계속 실행**합니다. Ready 메시지가 나오면 브라우저에서 **Ctrl+F5**를 누르세요. **이 CMD 창을 닫으면 서버와 Cloudflare 터널의 하위 프로세스까지 자동 종료됩니다.** 창을 열어 둬야 외부 접속도 유지됩니다. Windows Job Object와 부모 프로세스 감시를 사용하므로 창/실행기를 강제 종료해도 서버가 분리되어 남지 않습니다.

터널 없이 로컬만 실행하려면 `start-server.bat -NoTunnel`, 기존 빌드를 재사용하려면 `start-server.bat -NoTunnel -SkipBuild`를 실행합니다. 별도 터미널의 `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1`로도 종료할 수 있습니다. `npm run serve`도 실행 터미널이 열려 있는 동안 유지됩니다. 작업 디렉터리와 관계없이 종료하려면 스크립트의 전체 경로를 사용합니다.

CMD에는 서버 상태와 `[action]` JSON 로그가 실시간으로 표시됩니다. 로그인, 마을 입장/퇴장, 게임, 낚시 시작/결과/중단, 텃밭·요리 작업과 획득·소비, 자율 설정, 오프라인 정산을 사용자 ID와 함께 확인할 수 있습니다. `logs/server.log`와 `logs/server-error.log`, 터널의 `logs/tunnel.log`/`logs/tunnel-error.log`에도 누적 저장합니다. 대화·기억 원문, 비밀번호, 쿠키, 설문 답변은 행동 로그에 포함하지 않습니다. 매 프레임 이동은 기록하지 않습니다. 로그 자동 회전은 후속 작업입니다.

다음 개발 세션의 우선순위, 미검증 항목, 코드 위치와 데이터 보호 규칙은 [후속 작업 인수인계](docs/NEXT_SESSION.md)에 정리했습니다.

Node.js 22.13 이상과 `cloudflared`가 필요합니다. 현재 PC에는 둘 다 설치되어 있습니다.

```powershell
cd D:\Github\PIEONA_v3_prototype
npm install
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

`.env`의 `GEMINI_API_KEY=`에 실제 키를 입력합니다. 키 값은 브라우저로 전달하지 않습니다. 기본 모델은 `gemini-2.5-flash`이며 `GEMINI_MODEL`로 바꿀 수 있습니다. 현재 .env의 `gemini-3-flash`는 API가 제공하는 정식 식별자인 `gemini-3-flash-preview`로 보정합니다. 키가 비었거나 Google이 `API_KEY_INVALID`로 거절하면 **로컬 체험 모드**임을 표시하며 대화·기억 저장·게임·소셜을 체험할 수 있습니다. 로컬 모드는 규칙 기반이며 실제 LLM 품질 검증용이 아닙니다. 유효한 키의 할당량·네트워크·모델 오류는 사용자에게 재시도 안내를 표시합니다.

```powershell
npm run serve
```

이 명령은 빌드 후 웹서버와 터널을 **숨김 백그라운드 프로세스**로 시작합니다. 실행 기록은 `logs/`에 있습니다. 이미 실행 중인 프로세스는 재사용합니다. `.env` 또는 **서버 코드** 수정 후에는 아래처럼 종료하고 다시 시작해야 합니다. 프런트엔드는 빌드 결과를 제공합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/stop.ps1
npm run serve
```

Cloudflare 없이 로컬에서만 실행:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/start.ps1 -NoTunnel
```

개발 모드: `npm run dev` → http://127.0.0.1:5173 (API는 3000). 운영 서버와 같은 3000 포트를 쓰므로 운영 서버를 먼저 종료합니다. `npm start`는 빌드된 화면과 API를 현재 터미널에서 실행합니다. PC가 꺼지거나 절전 상태이면 외부에서도 접속할 수 없습니다. Windows 재부팅 후 `npm run serve`를 다시 실행합니다. Windows 서비스/자동 실행 등록은 하지 않았습니다.

## Cloudflare 연결

전용 터널 `pieona-avatar-prototype`을 만들고 `pieona.yoosung.dev`의 DNS를 연결했습니다. `cloudflare/config.yml`은 `http://127.0.0.1:3000`으로 전달하며, 나머지 호스트는 404를 반환합니다. 외부에서 노출하는 서비스는 이 호스트 하나입니다. 서버는 기본적으로 루프백에만 바인딩합니다.

- 터널 자격 증명: `data/cloudflare/credentials.json` (비밀, Git 제외)
- 터널 UUID: `0339e6c9-1d85-46c4-8b78-c4aecd4ef7fe`
- 설정 검증: `cloudflared tunnel --config cloudflare/config.yml ingress validate`
- 터널 단독 실행: `npm run tunnel`
- 원격 관리 터널을 쓰려면 `.env`의 `CLOUDFLARE_TUNNEL_TOKEN`을 설정하고 Cloudflare 대시보드의 공개 호스트도 같은 로컬 서버로 지정합니다. 토큰은 명령 인자나 로그로 출력하지 않습니다.
- 포트를 바꿀 경우 `.env`의 `PORT`와 `cloudflare/config.yml`의 `service`를 함께 바꿉니다.
- 다른 PC로 옮길 때 SQLite 데이터와 터널 자격 증명도 별도로 옮겨야 합니다. 자격 증명 파일을 공유 저장소에 올리지 마세요.

참고: [Cloudflare 로컬 터널 설정](https://developers.cloudflare.com/tunnel/features/locally-managed-tunnels/configuration-file/), [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output).

## 플레이 흐름

주요 실행 버튼은 진한 파란색과 굵은 글씨로, 보조 행동은 테두리 버튼으로 구분합니다. 선택한 메뉴·탭·꾸미기 항목과 키보드 포커스도 선명하게 표시합니다.

내 정원에서 **내 마을 걷기**를 누르거나 **WASD / 방향키**를 누르면 마을 전체 보기로 전환해 내 캐릭터를 움직입니다. 카메라를 돌려도 화면 방향에 맞춰 이동하며, 마을 밖으로 나가지 않습니다. 한글 키보드에서도 WASD의 물리 키를 사용합니다. 메시지·검색 입력, 안내·꾸미기·게임 창, 이웃 목록 조작 중에는 이동하지 않습니다. 내 마을 이동은 실시간 연결 준비 중에도 가능합니다. **아바타와 이야기**로 대화 화면에 돌아갑니다.

마을의 기본 벤치와 꾸미기로 배치한 벤치에 가까이 가면 **C 눌러 앉기** 안내가 나타납니다. C를 누르거나 안내 버튼을 터치하면 벤치 방향으로 앉고 카메라가 부드럽게 가까워집니다. 앉은 뒤에도 드래그로 회전하고 휠로 거리를 조절할 수 있습니다. 다시 **C**를 누르면 일어나며 앉기 전 카메라 시점으로 돌아갑니다. 앉아 있는 동안 이동·점프는 멈추며, 네 캐릭터 모두 뼈대 기반 앉기·일어나기 애니메이션과 이웃에게 보이는 자세 동기화를 지원합니다. 보관한 벤치에는 앉을 수 없고, 마을 보기에서 나가면 일어납니다.

상단 BGM 버튼에서 제공된 `S_Vilage_v2.mp3` 배경음악을 재생·일시정지하고 음량을 조절합니다. 음악은 반복 재생하며, 브라우저 자동 재생 정책에 따라 첫 클릭/키 입력 또는 재생 버튼 이후 시작합니다. 로그인 화면부터 마을 이동까지 재생이 이어지고, 리듬게임·음성 입력 중에는 음량을 낮춥니다. 음악 설정은 이 브라우저에 저장됩니다.

대화창 오른쪽의 **접기 / 펼치기** 버튼으로 대화 영역을 토글합니다. 접어도 대화 기록·작성 중인 문장·진행 중인 응답은 유지되며, 접기 설정은 이 브라우저에 저장됩니다. 이웃 아바타와 새 대화를 시작하거나 지난 대화를 이어가면 대화창을 펼칩니다.

**새 대화**로 독립된 채팅 세션을 만들고 **세션**에서 해당 아바타와 나눈 대화를 다시 선택합니다. 첫 메시지가 제목이 되며 최근 대화 순으로 표시합니다. 새 세션은 이전 메시지 문맥을 가져오지 않지만 아바타의 기억·말투·가치관·초기 성향은 유지합니다. 세션을 전환할 때 작성 중인 문장은 현재 화면에서 세션별로 보관합니다. 방문자 새 대화에는 매번 공유 동의를 적용하며, 다른 자아 슬롯의 기록은 전체 기록에서 열람할 수 있지만 해당 자아로 전환해야 이어갈 수 있습니다.

내 아바타도 나의 취향과 말투를 가진 또 다른 자아로 대화합니다. 확인된 말투·가치관·취향은 현재 주제와 무관하게 기본 성향으로 전달하며, 직접 지정한 말투를 일반 기본값과 초기 선택보다 우선합니다. 일상 수다·농담·의견·계획에는 그에 맞게 답하고, 고민이나 도움을 요청할 때 공감과 조언을 제공합니다. 기억 정원에서 말투 기억을 확인·정정하면 다음 대화에도 적용됩니다.

1. 계정 생성 또는 로그인 → 아바타 닉네임 → 예시 그림이 있는 밸런스게임 5문항 → 상황별 주관식 답변 2문항. 취향과 말투 예시를 비공개 확인 기억으로 함께 저장하고, 완료 화면에서 내가 고른 성향과 표현을 확인합니다. 첫 대화부터 아바타의 말투 컨텍스트에 반영하며, 주관식의 가상 상황을 실제 경험으로 취급하지 않습니다.
2. 중앙의 실제 Meshy 캐릭터와 하단 입력창으로 대화. 지원 브라우저에서는 음성 입력과 응답 읽기도 사용합니다. 음성 인식은 브라우저/OS의 지원과 권한에 따라 동작합니다.
3. **기억 정원**에서 AI가 제안한 비공개 초안을 확인하고, 정정·삭제·공개 범위를 지정합니다. 확인한 기억의 종류와 다양성이 쌓이면 개화 단계가 올라갑니다.
4. 오른쪽의 실제 계정 목록에서 이웃 선택 → 탑뷰 마을 → 카페 또는 아바타 클릭. 접속 상태는 Socket.IO로 동기화하며, 오프라인 계정도 목록과 아바타 대화가 유지됩니다. 샘플 계정을 운영 데이터에 자동 생성하지 않습니다. 서로 다른 브라우저/시크릿 창에서 계정 두 개로 소셜 루프를 체험하세요.
5. 방문자 대화 전에 내용 공유 및 익명 표시를 선택. **도착한 이야기**에서 내 방문객·응원·미니게임·공유된 대화 전문을 확인합니다. 방문자가 공유를 철회하면 소유자 열람도 즉시 막힙니다.
6. **미니게임** 또는 카페에서 몽글 배구·게 게 게·별빛 리듬·구름 달리기를 선택합니다. **마을 기록**에서 현재 마을의 게임별 상위 30개 완료 기록을 소유자와 방문자 모두 볼 수 있습니다. 게임 시작 전 익명 표시를 선택할 수 있고, 보상이 없는 완료 기록도 남습니다. 카페에서 30초 리듬게임. D/F/J/K 또는 터치로 레인을 누릅니다. 서버가 입력 수신 시각을 기준으로 판정합니다. 인터넷 지연에 따라 판정 체감이 달라질 수 있습니다.
7. 친구 요청 → 상대 수락 → 원하는 친구를 절친으로 지정. 절친 공개 기억은 **기억 소유자가 절친으로 지정한 상대**에게만 보입니다.
8. 스페셜 토픽에서 두 아바타의 전체 공개 기억으로 4턴 교차 대화를 생성하고 JSON 이야기 카드를 저장합니다. 방문자 및 토픽 대화는 소유자의 영속 기억을 갱신하지 않습니다.
9. 홈의 **마을 꾸미기**는 팝업 대신 전체 화면 3D 편집 모드로 열립니다. 왼쪽 목록에서 21종 소품을 분류·검색하고, 소품을 선택한 뒤 빈 격자를 클릭하거나 목록에서 마을로 끌어 놓습니다. 배치한 소품은 드래그로 이동하며 **R**로 90도 회전, **Delete**로 삭제합니다. 방향키는 선택한 소품을 미세 이동합니다. 빈 공간 드래그는 카메라 회전, 휠은 줌, 두 손가락은 확대·이동이며 우측 버튼으로 시점을 초기화할 수 있습니다. **되돌리기 / 다시하기**(Ctrl+Z / Ctrl+Shift+Z)를 지원하며 **설정 완료**를 눌러 저장합니다. 저장하지 않고 나갈 때는 변경 사항 처리 여부를 확인합니다. 최대 24개를 배치하며 중앙 광장·산책로·기존 시설은 비워둡니다. 피어나 조각상은 보유 수량 제한이 없으며 전체 배치 한도 24개는 적용됩니다. **캐릭터 꾸미기**에서 모자 3종·액세서리 3종·색상 6종을 고릅니다. 꾸미기는 계정에 영구 저장되며 자아 슬롯을 바꿔도 유지됩니다. 모든 소품과 썸네일은 `src/worldAssets.js`의 실제 3D 모델을 사용합니다. 홈에서 편집 진입 시 같은 3D 장면의 카메라가 약 1.1초 동안 편집 시점으로 이동하고, 종료 시 진입 전 시점으로 돌아옵니다. 선택한 마을 테마의 하늘·조명·재질은 편집 중에도 유지됩니다. 모션 줄이기 설정을 켜면 시점 전환을 즉시 적용합니다.
10. **구름 달리기**는 5,000m를 완주하는 3D 장애물 게임입니다. 준비 시간 3초 후 약 107초 동안 달리며, 속도가 11m/s에서 2초마다 5m/s씩 올라 출발 16초 후 최대 50m/s를 유지하고 장애물 간 시간 간격도 짧아집니다. A/D 또는 좌우 방향키로 3개 레인을 이동하고 스페이스/위 방향키 또는 터치 버튼으로 0.5초 동안 짧게 점프합니다. 목숨은 3개이며 분홍 울타리는 모든 레인을 막으므로 점프로 피합니다. 밝은 초록색 링으로 둘러싸인 커다란 새싹 모양의 씨앗을 같은 레인에서 수집하면 개당 50점이 추가되고 짧은 획득 효과음과 떠오르는 +50점 표시가 나옵니다. 화면에서 거리·현재 속도·수집 개수를 확인할 수 있습니다. 서버가 입력 수신 시각을 기준으로 충돌·씨앗 수집·점수·보상을 계산합니다. 미니게임 창 바깥을 클릭해도 게임이 종료되지 않습니다. 닫기나 게임 목록 버튼으로 나가면 미완료 판을 취소하며 다시 시작할 수 있습니다.
11. 정원 테마 4종·프로필 편집·기억 정정과 삭제·스페셜 토픽·다중 자아 슬롯(최대 8개)은 모두 무료입니다. 설정의 자아 슬롯에서 생성·전환하며 각 슬롯의 기억과 밸런스 답변은 독립적으로 저장됩니다. 이웃에게는 선택한 대표 아바타가 표시됩니다. 게임 내 결제와 유료 티켓 제한은 없습니다.

## 같은 마을에서 실시간으로 만나기

마을마다 **팻말 하나**가 놓입니다. 팻말을 직접 클릭하거나 **팻말 보기**를 누르면 카메라가 약 1.1초 동안 팻말 앞으로 이동하며, **돌아가기**로 이전 시점에 복귀합니다. 주인에게만 **팻말 편집하기**가 표시됩니다. 첨부 디자인을 기준으로 그리기·지우기·되돌리기·다시하기·전체 지우기, 12색 팔레트, 브러시 크기, 판자·화살표·매달린 팻말 3종을 구성했습니다. 마우스와 터치로 그릴 수 있고 **저장하기**로 그림과 모양을 계정에 저장합니다. 취소·닫기·Esc는 변경 사항이 있으면 저장 여부를 확인합니다. 그림은 방문자에게도 표시되며 자아 슬롯과 관계없이 유지됩니다. 최대 300획·16,000개 점을 지원합니다.

**마을 꾸미기 → 마을 팻말**을 선택하면 드래그·방향키로 위치를, **R**로 방향을 조정하고 **설정 완료**로 저장합니다. 이동·회전에도 되돌리기·다시하기가 적용됩니다. 팻말은 소품 24개 제한에 포함되지 않으며 삭제·복제할 수 없습니다. 기존 마을에도 소품과 겹치지 않는 위치에 기본 팻말이 표시됩니다.

주인이 **내 정원**에 접속해 있으면 대화 화면과 걷기 화면에서 같은 마을 세션을 유지합니다. 방문자는 이웃 목록에서 주인의 마을로 들어갑니다. **내 마을 걷기 / 마을 둘러보기**에서 두 플레이어의 캐릭터를 보고 WASD / 방향키로 각각 이동할 수 있습니다. 화면 상단에 함께 있는 사람을 표시하고, 중앙의 **AI** 대역은 주인이 그 마을에 없을 때만 나타납니다. 주인이 다른 마을로 떠나거나 접속을 종료하면 표시되고, 돌아오면 사라져 주인과 방문자 두 플레이어만 남습니다. 대화 화면의 인물 클로즈업은 유지하며, 걷기 화면에서는 주인 캐릭터를 누르거나 **아바타와 이야기** 버튼으로 대화할 수 있습니다. 주인이 오프라인이어도 AI 아바타와의 기존 방문 대화는 유지됩니다.

모바일·터치 기기와 좁은 화면의 마을 보기에는 **터치 조이스틱**이 표시됩니다. 기울인 정도에 따라 속도가 달라지고, 카메라를 돌려도 화면 방향으로 이동합니다. 손을 떼거나 터치가 취소되거나 창을 벗어나면 멈추며, 대화 동의·꾸미기·게임 창에서는 조이스틱을 숨기고 입력을 초기화합니다. 조이스틱도 키보드와 동일한 위치 동기화를 사용합니다.

이동 중 위치·방향·걷기 상태를 약 10Hz로 같은 마을에만 중계하고 화면에서는 위치와 회전을 보간합니다. 정지 위치는 신뢰성 있는 이벤트로 전달하며, 입장 시 최신 위치를 받습니다. 연결 복구 시 현재 마을에 다시 입장하고 로컬 위치를 다시 전송합니다. 같은 계정의 여러 탭은 캐릭터 하나를 공유하며 마지막 탭이 떠나면 퇴장합니다. 다른 마을의 이동 이벤트와 늦게 도착한 이전 마을 응답은 적용하지 않습니다. 위치는 서버 메모리에만 유지하고 프레임별 DB 기록이나 별도 게임 서버는 사용하지 않습니다.

서버 코드와 소켓 메시지 형식이 함께 변경되었으므로 실행 중인 서버를 재시작하고 열려 있는 브라우저도 새로고침해야 합니다. 서로 다른 브라우저 또는 시크릿 창의 계정 두 개로 확인할 수 있습니다.

## 미니게임 다인 플레이

**게 게 게**와 **구름 달리기**는 솔로 및 2~8인 플레이를 지원합니다. 미니게임에서 함께할 친구를 최대 7명 선택하고 방을 만들면 모두에게 한 번에 초대합니다. 전원이 30초 안에 수락하고 준비하면 같은 시각에 시작하며, 거절·초대 취소·마을 이탈 시 초대 전체를 해제합니다. 준비 중 이탈하면 방을 취소합니다. 구름 달리기는 모든 참가자의 캐릭터와 순위를 표시하고, 시작 후 한 명이 나가도 다른 참가자의 경기와 기록 저장은 유지합니다. 배구는 솔로 AI전 또는 2인 대전을 지원합니다. 서버를 재시작하고 브라우저를 새로고침해야 변경된 소켓 흐름이 적용됩니다.

## 미니게임: 게 게 게

미니게임 **게 게 게**는 3D 탑뷰 해변 생존 게임입니다. WASD / 방향키 또는 모바일 조이스틱으로 움직이며, 시작부터 뒤따르는 게 두 마리와 해변의 순찰 게를 피합니다. 가까이 다가간 순찰 게는 추격 후 행렬의 꼬리에 합류합니다. 시간이 지날수록 더 많은 게와 빠른 순찰이 등장하며, 라이프는 3개이며, 자기 행렬을 포함한 게에 닿으면 1개를 잃고 1.5초 동안 무적이 됩니다. 마지막 라이프를 잃으면 게임오버됩니다.

해변의 버블은 먹자마자 발동합니다. **보라색**은 상대 행렬의 마지막 게 1마리를 내 꼬리로 강탈하고, **주황색**은 내 꼬리 게 1마리를 상대의 현재 위치로 빠르게 발사합니다. **민트색**은 7초 동안 모든 게 행렬을 지그재그로 바꿉니다. 솔로 강탈은 해변의 순찰 게를 데려오며, 솔로 발사는 이동 방향으로 나갑니다. 버블은 7초마다 추가 생성되고 22초 후 사라집니다. 시작·플레이·게임오버·승리 화면은 제공된 해변 이미지 스타일에 맞춰 개편했습니다.

혼자 플레이하면 생존 시간 0.1초당 1점에 더해, 기본 두 마리를 넘는 행렬의 게 한 마리당 유지 시간 1초마다 보너스 2점을 누적하고 20초부터 기존 게임들과 같은 일일 한도 안에서 골드를 받습니다. 같은 마을의 친구를 최대 7명 초대해 총 2~8명이 같은 해변과 게들을 공유할 수 있습니다. 초대한 친구 전원이 수락하고 준비하면 시작합니다. 참가자 모두 모든 게에 충돌할 수 있으며, 마지막 생존자가 승리하고 마지막 생존자들이 동시에 탈락하면 무승부입니다. 중도 이탈자는 기권하며 남은 인원끼리 계속합니다. 탈락하면 남은 생존자를 관전하고, 재대결은 기록 저장 후 전원의 동의가 필요합니다. 강탈은 게를 보유한 가장 가까운 생존자를, 발사는 가장 가까운 생존자를 대상으로 합니다. 점수판은 현재 초당 점수와 누적 행렬 보너스를 표시하며, 결과 화면에는 생존 점수와 보너스를 따로 보여줍니다. 순위는 합산 점수로 매기고 실제 생존 시간을 별도로 표시합니다. 익명 기록·마을 순위·중복 정산 방지도 적용됩니다. 이동은 매 프레임 즉시 예측하고, 서버가 확인한 입력 이후의 방향 전환·정지 입력을 다시 적용해 위치를 보정합니다. 카메라는 캐릭터를 따라가며 해안이 보이는 12m 기본 반시야를 사용합니다. 게임 중에는 배경 마을의 반복 렌더링을 멈추고, 상세 해변 배경과 인스턴스 게 스프라이트·접지 그림자·3D 버블을 사용합니다. 게임 그래픽과 음향 에셋의 출처 및 프롬프트는 `resource/crab-chase-assets.md`에 있습니다. 서버 코드 변경을 적용하려면 서버를 재시작해야 합니다.

## 마을 방명록

마을마다 팻말과 별도로 방명록이 하나씩 있습니다. **마을 꾸미기 → 마을 방명록**에서 이동·회전하고 저장할 수 있으며, 일반 소품 24개 제한과 별개로 유지합니다. 방명록 오브젝트를 클릭하거나 화면의 **방명록** 버튼을 누르면 팻말과 같은 1.1초 카메라 확대 연출로 책을 엽니다. 닫으면 이전 시점으로 돌아오며 모션 줄이기 설정도 따릅니다.

방문객과 주인 모두 최대 200자의 글을 남길 수 있습니다. 글마다 **익명으로 남기기**, **모두 공개 / 주인만 보기**를 선택합니다. 공개 글은 방문객 모두가 함께 보고, 주인만 보기 글은 작성자를 포함한 다른 방문객의 목록·개수에서 제외합니다. 익명 글의 이름과 작성자 계정 ID는 API에서 숨깁니다. 최신순으로 한 페이지에 4개씩 표시하며 이전·다음 버튼과 페이지 안 스크롤로 읽습니다. 주인은 모든 글을 확인하고 삭제할 수 있고, 방문객은 삭제할 수 없습니다. 작성·삭제는 접속 중인 같은 마을 화면에 반영됩니다.

글과 배치는 SQLite에 저장되어 재시작 후에도 유지하며 자아 슬롯을 바꾸어도 같은 마을 방명록을 사용합니다. 기존 DB에는 서버 시작 시 테이블이 자동 추가됩니다. 서버를 재시작하고 브라우저를 새로고침하면 기능이 적용됩니다.

## 프라이버시 구현 계약

| 정보 | 소유자 | 일반 방문자 | 승인된 절친 |
|---|---|---|---|
| 비공개 기억 및 미확인 초안 | 사용/관리 가능 | 프롬프트 및 API에서 제외 | 제외 |
| 확인한 전체 공개 기억 | 사용/관리 가능 | 읽기 전용 | 읽기 전용 |
| 확인한 절친 기억 | 사용/관리 가능 | 제외 | 소유자가 절친으로 지정한 경우 읽기 전용 |
| 소유자 대화 원문 | 본인만 열람 | 제외 | 제외 |
| 방문 대화 원문 | 방문자 내용 공유 + 소유자 수신 허용 시 열람 | 대화를 시작한 본인만 | 친구 여부와 무관 |
| 아바타 토픽 | 양측 전체 공개 기억만 | 양측 전체 공개 기억만 | 절친 기억도 제외 |

- 새 기억은 **소유자 인증 대화**에서만 비공개·미확인 초안으로 추가합니다. 초기 밸런스 답변은 비공개 확인 기억으로 저장합니다.
- 공개 자기소개·관심사·말투는 명시적으로 편집하는 공개 데이터입니다. 비공개 소유자 기억을 자동으로 공개 프로필에 옮기지 않습니다.
- RAG는 한국어 바이그램/단어 일치와 확인 여부·최신성으로 순위를 계산합니다. **권한 필터 후 검색**하며, 관련 기억 10개에 확인된 말투·가치관·취향 각 최대 4개 및 최신 직접 말투 선호 최대 4개를 중복 제거해 전달합니다. 소유자 대화에서는 직접 알려준 새 말투를 초안 상태에서도 적용하며, 방문자에게는 확인·공개된 말투만 전달합니다. 핵심 성향에도 같은 공개 범위 필터를 적용합니다. 외부 벡터 DB·임베딩 비용이 없습니다.
- 방문자의 원문 대화 기록만 해당 방문자 세션에 사용합니다. 소유자 원문과 다른 방문자의 대화는 모델에 전달하지 않습니다.
- 기억 수정·삭제·권한 변경 시 컨텍스트 지문이 바뀌며 이전 대화 히스토리를 다음 추론에서 제외합니다. 추론 도중의 변경도 재확인해 응답 저장과 전달을 막습니다. 다만 이미 상대 화면에 표시됐거나 상대가 저장한 공개 대화는 회수할 수 없습니다.
- 비공유 방문도 방문 사실은 남으며, 전문은 양측 동의 때만 열립니다. 익명 설정은 소유자에게 보이는 이름과 계정 ID를 숨깁니다. 익명은 서버 운영자에게까지 숨기는 기능은 아닙니다.
- 차단 시 양쪽의 프로필/아바타 대화/기록 열람이 차단됩니다. 설정에서 해제할 수 있습니다. 신고는 PC 서버의 `reports` 테이블에 저장됩니다.
- 비밀번호는 랜덤 솔트를 사용하는 scrypt, 세션은 HttpOnly/SameSite 쿠키 및 DB 내 토큰 해시로 저장합니다. HTTPS 요청에는 Secure 쿠키를 사용합니다. 요청 출처 제한과 인증·AI 요청 속도 제한이 있습니다.
- 데이터는 자동 만료 없이 PC에 보관합니다(로그인 세션 30일). 대화를 시작한 본인은 대화 기록을 삭제할 수 있고, 소유자는 자기 기억을 삭제할 수 있습니다. 설정에서 본인 데이터를 내려받을 수 있습니다.
- SQLite 파일과 백업은 서버 운영자가 접근할 수 있는 일반 파일입니다. 개별 기억의 저장 암호화·클라이언트 종단간 암호화는 구현하지 않았습니다. 운영 PC의 디스크 암호화/접근 제어 범위에서 보호됩니다.

## 서버 데이터와 보상

`data/pieona.sqlite`에 계정·기억·친구·활동·대화·게임·플레이테스트 이벤트를 저장합니다. SQLite WAL 모드로 여러 접속의 쓰기를 단일 서버에서 직렬 처리합니다. 여러 Node 프로세스/여러 PC의 수평 확장은 대상이 아닙니다.

- 방문 보상: 유효 대화·응원·게임 활동 완료 후 고유 방문자 1명당 한국 날짜 기준 하루 1회 10G, 소유자 하루 최대 200G.
- 리듬게임: 서버 판정 8개 이상 성공 시 `30 + floor(score / 100)`G. 같은 마을 하루 3회, 하루 총 300G 한도. 점수/보상을 클라이언트 요청으로 지정할 수 없습니다. 완료 재요청도 중복 정산하지 않습니다.
- 달리기: 서버가 확인한 장애물 통과 8개 이상일 때 리듬게임과 같은 보상식과 한도를 공유합니다. 점수는 달린 시간과 통과한 장애물로 계산합니다. 중단한 게임은 순위에서 제외합니다. 기존 완료 리듬 기록도 DB 마이그레이션으로 점수를 복원합니다.
- 테마와 토픽은 골드를 소모하지 않습니다. 골드는 플레이 보상과 반복 동기 가설을 확인하는 지표입니다.
- 부정 다중 계정을 완전히 막는 본인 인증이나 자동화 탐지는 포함하지 않았습니다.
- 백업: 서버를 `scripts/stop.ps1`로 종료한 후 `data/pieona.sqlite`를 날짜가 붙은 별도 파일로 복사하세요. 운영 중 복사 시 `.sqlite-wal`을 누락하면 최신 데이터가 빠질 수 있습니다. 터널 자격 증명은 별도로 보관합니다.

## 재미 검증

상단 **설문**에서 4개 Part, Q1~Q11의 플레이 설문에 참여할 수 있습니다. 미참여 계정에는 미니게임 1회 완료, 내 아바타와 성공한 대화 10회, 다른 아바타와 성공한 대화 5회 중 하나를 충족하거나 로그아웃을 누르면 피오 캐릭터와 함께 참여를 요청합니다. 대화와 게임 조건은 서버 누적 이벤트로 판정하며, 중단한 게임과 실패한 대화는 제외합니다. **나중에 할게요** 또는 창 닫기/ESC를 선택하면 자동 요청을 24시간 미루며, 상단 버튼에서는 바로 참여할 수 있습니다. 로그아웃 과정에서는 제출 또는 미루기 후 로그아웃을 이어갑니다. 제출한 계정에는 다시 요청하지 않습니다.

`survey_participation`에는 계정별 완료 여부와 미루기 시간만 저장하고, `survey_responses`에는 임의 응답 ID·설문 버전·응답만 저장합니다. 응답에 계정 ID, 닉네임, 이메일, 제출 시각을 추가하거나 계정 이벤트에 응답을 기록하지 않습니다. Q1/Q8 복수 선택, Q4 최대 2개, Q5/Q7 단일 선택을 서버에서도 검증합니다. Q2/Q3에는 미경험 응답이 있고 Q10/Q11은 선택 응답입니다. 현재 설문 이전의 `playtest_feedback` 이벤트는 기존 데이터로 유지되며 새 응답 저장에는 사용하지 않습니다.

첫 테스트에서는 두 명 이상이 각자 자기 아바타와 3~5회 대화하고, 기억을 확인·공개한 뒤 서로의 마을에서 대화와 카페 연주를 진행하도록 권합니다. 이후 방문 로그를 확인하고 설문에 답하면 **나를 닮는 발견 → 이웃의 관심 → 답방**의 핵심 가설을 관찰할 수 있습니다. 기능 구현 완료는 재미가 검증됐다는 뜻이 아니며, 실사용자 플레이테스트 결과로 판단합니다.

첫 로그인 후 간단한 게임 설명을 보여주고 왼쪽 **게임 안내**에서 다시 볼 수 있습니다. 로그인 화면에도 핵심 플레이 설명을 표시합니다. 안내 대상은 실제 화면을 그대로 드러내고 나머지 영역만 어둡게 흐리며, 친구 단계는 오른쪽 친구·이웃 목록 탭을 가리킵니다. 좌측 놀이터·친구·설문 버튼은 제거하고, 미니게임은 마을 활동에서 실행합니다.

홈의 **STAGE MODE**에서 정원·모닥불·카페·황혼·노을을 선택하면 계정의 마을 테마로 즉시 저장되어 재접속과 방문자 화면에도 유지됩니다. 소품 편집과 같은 저장값을 사용하고, 테마만 바꾸면 소품 배치는 보존합니다. 모닥불과 황혼에는 달·별을, 모닥불에는 움직이는 불꽃과 불씨를 표시합니다. **앨범**은 좌측 사이드탭에서 엽니다. **캡처**는 현재 3D 시점의 편집용 초안을 열며, 이때는 앨범에 저장되지 않습니다. 제목·메모·프레임을 꾸미고 **앨범에 저장**을 눌러야 최종 사진이 보관됩니다. 저장하지 않고 나갈 때는 편집 내용 처리 여부를 확인합니다. 제목·최대 400자 메모·태그·즐겨찾기를 편집하고, 잎사귀·벚꽃·별빛·바다·스크랩·기본형의 6가지 프레임과 날짜·시간 표시를 선택할 수 있습니다. **PNG 다운로드**는 앨범에 저장한 최종 사진을 내려받으며, 원본 비율의 사진·프레임·날짜와 제목·메모·태그·장소가 PNG 안에 함께 들어갑니다. 긴 제목과 여러 줄 메모는 줄바꿈하고 이미지 높이를 늘려 모두 담습니다. 기존 사진을 수정할 때도 저장을 눌러 최종본을 갱신합니다. 기억 저장소 내부의 도감 버튼과 캐릭터별 탭은 제거했습니다. 앨범은 검색·정렬·즐겨찾기·격자/목록 보기와 사진 삭제를 지원하며 마을의 5가지 테마 색상을 따릅니다. 사진과 기록은 현재 브라우저의 IndexedDB에 자아별로 보관되므로 새로고침 후에도 유지됩니다. 다른 기기와 동기화되지 않으며 브라우저 데이터를 삭제하면 사라지므로 소중한 사진은 PNG로 내려받으세요. 저장 공간이 부족하면 작성한 초안을 유지하고 다시 저장할 수 있도록 안내합니다.

기획서의 UE5/온디바이스 sLLM·모바일 배터리 연구, 전신 의상 교체, QR/영상 클립, 푸시 알림, 설문 이외의 운영자 대시보드는 이 웹 수직 프로토타입의 구현 범위에 포함하지 않습니다. 정기 질문은 접속 중 화면 제안으로 제공하며 설정에서 빈도·주제·건너뛰기를 제어합니다.

## 설문 통계와 권한 관리

`안녕하세요유성입니다잘부탁드립니다` 닉네임의 기존 `hys8623` 계정은 설문 관리자입니다. DB를 열 때 이 계정의 고유 ID로 관리자 권한을 적용하므로 닉네임·자아 슬롯 변경으로 권한이 바뀌거나 다른 사용자가 같은 닉네임으로 관리자가 되지 않습니다. `users.survey_role`에 일반 회원(`user`)·매니저(`manager`)·관리자(`admin`) 권한을 보관하며 재시작 후에도 유지합니다.

관리자와 매니저에게 웹 상단의 **설문 통계** 버튼이 표시됩니다. 현재 설문 버전의 응답 수, Q1~Q11 선택 분포·비율, 평가 평균과 미경험 응답 수, 페이지별 익명 주관식·기타 의견을 확인합니다. 평균은 미경험 응답을 제외하고 선택 비율은 문항 응답자 수를 기준으로 계산합니다. 복수 선택의 합은 100%를 넘을 수 있으며, 이전 버전의 응답은 별도 건수로 안내합니다. 응답자의 계정·닉네임·제출 시각은 통계에 포함하지 않습니다.

관리자는 같은 화면의 **매니저 관리** 메뉴에서 아이디·닉네임으로 계정을 검색해 **매니저 부여 / 권한 회수**를 선택합니다. 매니저에게는 통계 조회만 허용하며 관리자 권한 변경은 제공하지 않습니다. 통계·의견 조회와 권한 변경 API는 매 요청마다 DB의 권한을 확인합니다. 권한 변경은 당사자의 접속 중인 모든 탭에 반영되며 권한 회수 시 열린 통계 화면을 닫습니다. 새 설문 제출은 조회 권한이 있는 연결에만 변경 알림을 보내고, 통계 화면은 재연결·화면 복귀와 15초 주기 확인으로 최신 데이터도 가져옵니다. 권한을 부여·회수한 관리자와 변경 대상은 `survey_role_changed` 이벤트로 기록하며 설문 답변은 이벤트에 기록하지 않습니다.

검증: `node --test --test-concurrency=1 tests/survey.test.mjs tests/survey-statistics.test.mjs`.

## 몽글 배구 (2026-10-18)

**마을 활동 → 미니게임 → 몽글 배구**에서 **혼자 플레이**를 선택하면 간단한 AI와 1대1로 대결합니다. **친구와 함께 플레이**에서는 같은 마을의 친구 한 명을 초대하고 두 사람 모두 준비한 뒤 같은 코트에서 대결합니다. [피카츄 배구 웹 버전](https://gorisanson.github.io/pikachu-volleyball/en/)의 좌우 이동·점프·스파이크 중심 플레이를 참고하고, 새싹 캐릭터와 해변 그림은 Canvas/SVG로 직접 구성했습니다.

A/D 또는 좌우 방향키로 이동하고, W/위 방향키로 점프하며, Space/Z로 스파이크합니다. 화면 아래의 터치 버튼으로도 조작할 수 있습니다. 몸에 공이 닿으면 자동 리시브하며, 공중에서 공이 닿기 직전 스파이크를 누르면 빠르게 공격합니다. 공이 내 코트 바닥에 닿으면 상대 득점, 7점 선승입니다. 최대 3분 후에는 더 높은 점수의 선수가 승리하며 동점이면 무승부입니다. 서브는 자동으로 진행하고 실점한 쪽에서 다음 서브를 시작합니다.

AI는 공의 착지를 대략 예측해 이동·점프·스파이크하며, 반응 지연과 예측 오차가 있습니다. 공·네트·선수 충돌, 득점, 승패와 기록은 서버에서 계산합니다. 점수는 득점당 100점에 승리 시 300점이며, 20초 이상 정상 완료한 경기는 기존 게임들의 마을별 하루 3회·하루 300골드 한도를 공유합니다. 중단한 경기는 기록하지 않고 상대가 떠나면 남은 선수가 기권승하며, 기권승에는 골드를 지급하지 않습니다. 연결이 끊긴 솔로 경기는 재접속 후 새 경기로 다시 시작할 수 있습니다.

추가 검증: `node --test --test-concurrency=1 tests/volleyball.test.mjs tests/volley-server.test.mjs`로 물리·AI 리시브·스파이크·시간 제한·입력 소유권·익명 기록·중복 정산·친구 초대와 기권을 검사합니다.

배구 화면은 입력 이력을 유지하는 연속 예측과 서버 확인 이후 입력 재적용으로 위치를 보정합니다. 화면 위치는 보간하고 정적인 코트 배경은 재사용하며, 점수판 갱신을 제한해 렌더링 부담을 줄였습니다. 서버와 경기 시작 시각을 맞추고 네트워크 공백의 예측 시간도 제한합니다.
